# 0001 — Initial setup: layered Express server + separate Vite/React client

## Status

Accepted

## Context

Проєкт стартував як набір статичних HTML-мокапів (`diff-*.html`), що фіксували візуальну мову
("git diff / code review") без жодного бекенду. Потрібно було вибрати архітектуру для реального
full-stack застосунку (auth, генерація питань AI, збереження історії співбесід), не
переписуючи мокапи одразу — вони лишаються джерелом правди для UX, поки `client/` не досягне
паритету (див. `PROGRESS.md`).

Ключові обмеження:
- Домен (теми/рівні співбесіди, структура фідбеку) буде змінюватися на ранній стадії продукту.
- Оцінка відповідей делегована зовнішньому LLM (Anthropic), а не власній ML-моделі — інтеграцію
  потрібно тримати замінюваною.
- Одна людина веде і клієнт, і сервер — над-абстракції (мікросервіси, GraphQL-шар,
  monorepo-пакети спільних типів) додали б координаційні витрати без поточної потреби.

## Decision

- **Сервер**: Express + TypeScript + Mongoose, layered за принципом
  `routes → controllers → services → models` (деталі й dependency rule — `ARCHITECTURE.md`).
  AI-виклики ізольовані в `src/services/ai.service.ts`, а не розкидані по контролерах.
- **Клієнт**: окремий Vite + React 19 + TypeScript SPA у `client/`, що спілкується з сервером
  лише через HTTP API — без спільного npm-пакета типів між клієнтом і сервером.
- **База даних**: MongoDB через Mongoose — документо-орієнтована модель добре лягає на "сесія
  співбесіди з масивом питань/відповідей", що змінюється по формі частіше, ніж дозволяла б
  жорстка реляційна схема на цьому етапі.
- **Auth**: JWT (httpOnly cookie) + Google OAuth і email/password з `bcryptjs` — без окремого
  auth-сервісу чи сесійного стору (Redis тощо), поки масштаб не вимагає.

## Consequences

- Дублювання домену (типи, enum-и `TOPICS`/`LEVELS`) вручну між `client/src/types/interview.ts`
  і `src/models/InterviewSession.ts` — прийнятний компроміс, поки немає monorepo-інструментів;
  задокументовано в `CLAUDE.md`, щоб зміни вносилися по обидва боки свідомо.
- Заміна AI-провайдера чи додавання другого (fallback-модель) торкається лише
  `ai.service.ts` — контролери й routes не потребують змін.
- Mongoose без формальних міграцій означає, що зміна форми документа (нове поле, зміна enum)
  не має автоматичного шляху відкату — `make migrate` поки що документаційний placeholder,
  доки схема не стабілізується настільки, щоб виправдати міграційний інструмент.
- Мокапи (`diff-*.html`) і `client/` тимчасово співіснують — легко переплутати, який файл
  редагувати; це явно проговорено в `CLAUDE.md`, щоб уникнути випадкових правок мертвого коду.
