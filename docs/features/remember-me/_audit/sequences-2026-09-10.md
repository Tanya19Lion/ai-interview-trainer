## Added

- **US-01: Choose to stay signed in** — happy path (login, `rememberMe: true`, both cookies
  issued) + 3 `alt` branches: `400 auth.missing_credentials`, `401 auth.invalid_credentials`,
  `429 auth.rate_limited` (ADR-0003).
- **US-02: Understand why I was signed out** — 2 `alt` branches, both ending in a clear
  non-redirecting message: `401 auth.refresh_token_expired` (AC-03) vs
  `401 auth.session_revoked` (AC-04/AC-07, tokenVersion mismatch) — the first sequence in this
  feature to draw both causes side by side.
- **US-03: Trust that resetting my password protects my account** — cross-feature sequence:
  `forgot-password`'s `confirmPasswordReset` bumps `User.tokenVersion`, then a later
  `refreshSession` call with the pre-reset `refreshToken` is rejected, plus an explicit replay
  `alt` branch (AC-04, no grace period).
- **US-04: Get the same choice regardless of how I log in** — 3-way `alt` (Google OAuth /
  email+password login / email+password register), all converging on the same cookie-issuance
  rule (AC-06).
- **US-05: Default to a short session** — happy path with only an access cookie issued (no
  `refreshToken`), 2 `alt` error branches, plus a client-side note on why browser-close ends the
  session with no server round-trip (session cookie, no `Max-Age`).
- **US-06: Trust that logging out ends my remembered session** — `alt` branch for
  valid-cookie-present (bumps `tokenVersion`) vs. no-cookie (graceful 200 no-op, not an error) —
  the no-op branch was a real gap in the original "Critical flow 3", which assumed a cookie was
  always present. Plus an explicit post-logout replay-rejected flow.

All 6 blocks inserted under `### US-N: <title>` headings in `sad.md` §6, after the 4 existing
"Critical flow" blocks. **Additive only** — none of the 4 existing blocks were modified.

## Validation

`mmdc` version has no `--parse-only` flag; full SVG render used as the equivalent syntax check).
Two blocks (US-02, US-05) initially failed — both had a `;` inside a `Note over ...:` line, which
this Mermaid version's sequence-diagram grammar treats as a statement separator, truncating the
note and corrupting the next line's parse. Fixed by replacing `;` with `,` in both notes; both
re-validated clean. Worth remembering for future sequence-diagram authoring in this repo:
**avoid semicolons inside Note text**, even though they render fine inside a plain message
(`->>`) line.
