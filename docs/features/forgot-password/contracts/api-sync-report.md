## Section B — drift findings

1. **Endpoint ↔ data-model** — ✓. `requestPasswordReset` creates a `PasswordReset` doc; `confirmPasswordReset` consumes one (`findOneAndDelete` by `tokenHash`) and writes `User.passwordHash` + bumps `User.tokenVersion`; `changePassword` writes `User.passwordHash` + bumps `User.tokenVersion`. Both entities in `data-model.md` are touched.
2. **Error codes ↔ domain sentinels** — **deferred to implementation time**. No error-constants module exists yet in `src/` (existing auth errors are inline strings in `auth.controller.ts`, not a shared sentinel module) and this feature is unimplemented — contract precedes code. Not scored as a failure per protocol's explicit allowance for this case.
3. **Validation ↔ persistence constraints** — ✓. `newPassword` `minLength: 8` matches PRD's stated policy (no equivalent constraint exists on `passwordHash` in `data-model.md`, correctly — it's a derived hash, not user input). `token` is now fixed at `minLength: 64, maxLength: 64, pattern: ^[0-9a-f]{64}$` — tightened (2026-09-09) from a loose 32–128 inferred range after `sad.md` §6 US-01 confirmed the generation step ("Generate raw token, hash it (sha256)") and the project's own `crypto.randomBytes(32).toString('hex')` convention.
4. **Entity ↔ endpoint** — ✓. `User` served by `confirmPasswordReset` + `changePassword`; `PasswordReset` served by `requestPasswordReset` (create) + `confirmPasswordReset` (consume). No orphan entities.
5. **OpenAPI ↔ sequence** — ✓ (resolved 2026-09-09). `complete-sequence-diagrams` added 5 new `### US-N:` sequences to `sad.md` §6 with `alt` blocks (`_audit/sequences-20260909.md`): US-01 (unknown email / rate-limited / Google hint), US-02 (valid vs. invalid/expired/used token), US-03 (Google-only / wrong current password / success), US-04 (both Google dead-end entry points), US-05 (TTL-expired vs. already-used). All three previously PRD-only error codes (`password_reset.invalid_or_expired_token`, `auth.invalid_current_password`, `auth.google_account_no_password`) now also trace to a sequence `alt` branch, not just an acceptance criterion.

## Reconcile run — 2026-09-09 (`--update`)

was added to `data-model.md` (Schema-change log entry above) without touching the contract first.

   `RequestPasswordResetResponse` in `openapi.yaml`, with an origin comment and a filled example
   value (`attemptsRemaining: 2`).
5. Re-ran `npx openapi-typescript` → regenerated types now include the field; the same consumer
   file recompiled with `tsc --strict` and **passed**, zero errors.
6. Drift check 3 re-run: ✓. No other check regressed.
