# SPEC.md

## Goals

- Дати користувачу пройти симуляцію технічної співбесіди: обрати тему (React, JavaScript,
  Node.js, TypeScript) і рівень (Junior/Middle/Senior), отримати від AI згенеровані питання,
  ввести відповідь текстом і отримати структурований фідбек (оцінка, пояснення помилок,
  правильна відповідь, рекомендовані теми для повторення).
- Автентифікувати користувача через Google OAuth і email/password (JWT-сесія), зберігати
  історію пройдених співбесід у MongoDB і показувати прогрес/статистику по темах і рівнях.
- Тримати клієнт (`client/`, Vite + React 19 + TS) і сервер (`src/`, Express + TS + Mongoose)
  як окремі проєкти зі своєю типізацією домену — без спільного npm-пакета.

## Non-goals

- Голосові/відео співбесіди, live-код-редактор з виконанням коду в пісочниці — тільки
  текстова відповідь, що оцінюється AI як diff/рев'ю коду.
- Мультикористувацькі команди, ролі, платні тарифи — на цьому етапі один тип користувача.
- Власна ML-модель — оцінка відповідей повністю делегована зовнішньому AI API
  (`ANTHROPIC_API_KEY`, див. `src/services/ai.service.ts`), нічого не тренується локально.

## Technical decisions

- **Стек**: Express + TypeScript + Mongoose на бекенді, React 19 + Vite + TypeScript на
  фронтенді; MongoDB як єдине джерело правди для юзерів та історії сесій.
- **Auth**: JWT (підписаний `JWT_SECRET`, термін дії `JWT_EXPIRES_IN`) у httpOnly cookie;
  паролі хешуються `bcryptjs`; Google OAuth верифікується через `google-auth-library` за
  `GOOGLE_CLIENT_ID`. Немає dev-заглушки логіну — тільки реальні шляхи автентифікації.
- **AI-інтеграція**: генерація питань і оцінка відповідей ізольовані в
  `src/services/ai.service.ts`, контролери (`interview.controller.ts`) не звертаються до
  Anthropic SDK напряму — це дає змогу підмінити провайдера, не займаючи routes/models.

## Acceptance criteria

- Користувач може зареєструватися/увійти (Google або email+password), отримати сесію, і при
  недійсному/відсутньому JWT отримувати 401 на захищених `/api/*` маршрутах.
- Користувач може обрати тему+рівень, отримати питання, надіслати відповідь і побачити фідбек
  (оцінка + пояснення + правильна відповідь) без ручного оновлення сторінки.
- Завершена сесія співбесіди зберігається в MongoDB (`InterviewSession`) і відображається в
  історії користувача зі статистикою по темах/рівнях (`/api/history`, `/api/stats`).
